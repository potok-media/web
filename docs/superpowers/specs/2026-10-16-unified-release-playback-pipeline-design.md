# Единый pipeline выбора раздачи и запуска просмотра

Дата: 2026-10-16

## Цель

Свести фильмы, сериалы, аниме, прямые потоки и совместный просмотр к одному предсказуемому сценарию. Пользователь всегда понимает:

- какую раздачу он открыл;
- какие файлы в ней обнаружены;
- как файлы сопоставлены произведению или эпизодам;
- почему запуск разрешён или заблокирован;
- какой файл и какая каноническая сущность сейчас воспроизводятся.

Автоматический полноэкранный запуск запрещён. Полноэкранный режим включается только явной кнопкой плеера.

## Принятые продуктовые решения

1. Любая торрент-раздача сначала открывает встроенный список файлов. Количество файлов и тип произведения не дают права пропустить этот шаг.
2. Прямой HLS/MP4-поток фильма может запускаться сразу, поскольку внутри него нет неизвестного набора файлов.
3. Для фильма содержимое торрент-раздачи не классифицируется автоматически как «основной фильм», «трейлер» или «бонус». Показываются все видеофайлы, а пользователь выбирает нужный.
4. Для сериала или аниме воспроизведение всей раздачи блокируется, пока в ней есть неоднозначные или неразрешённые воспроизводимые файлы. Это не позволяет автопереходу или ручному выбору записать прогресс не в тот эпизод.
5. Старый список файлов сохраняется функционально, но больше не является модальным окном. Он встроен в правую часть единого workspace.
6. Плеер, очередь и панель совместного просмотра имеют одну реализацию для хоста, гостя, фильма, сериала и аниме.
7. Верхняя панель приложения остаётся видимой во всех состояниях, кроме настоящего browser fullscreen, включённого пользователем.

## Выбранный подход

Используется одна машина состояний вместо набора независимых флагов `clickedStream`, `episodeSelectorData`, `presentation`, `showRightRail` и специальных полноэкранных веток.

Альтернативы отклонены:

- условный рендер поверх существующих флагов сохраняет несовместимые комбинации состояний и уже привёл к разным панелям;
- отдельные маршруты для выбора файлов, исправления и просмотра усложняют навигацию и разрывают единый контекст раздачи.

## Внешний pipeline

```text
Список раздач
    ↓ выбрать
Проверка источника
    ├─ прямой фильм → подготовка потока
    └─ торрент → загрузка файлов
                    ↓
              проверка соответствий
                    ├─ корректно → выбор файла/эпизода
                    └─ проблемы → исправление → повторная проверка
                                          ↓
                                  подготовка потока
                                          ↓
                                  inline-плеер + очередь
```

Переход к следующему состоянию выполняется только после успешного завершения предыдущего. Поздний ответ от ранее выбранной раздачи не может изменить текущее состояние.

## Машина состояний

### `browsing`

Показывается список найденных раздач. Плеер и панель файлов не смонтированы.

События:

- `SELECT_RELEASE` → `inspecting` для торрента;
- `SELECT_RELEASE` → `preparing` для прямого фильма;
- смена источника или обновление поиска остаются в `browsing`.

### `inspecting`

Загружается и нормализуется содержимое выбранной раздачи. Слева показывается preview произведения и название раздачи, справа — skeleton будущего списка файлов.

Результаты:

- файлы получены и валидны → `ready`;
- найдены проблемы соответствий → `blocked`;
- файлов нет или источник не ответил → `failed`.

### `blocked`

Справа отображается список файлов с явными статусами. Кнопки запуска и автопереход отключены. Доступна одна основная операция — «Исправить соответствия».

После сохранения исправления источник повторно возвращает полный нормализованный список. Клиент не исправляет локальную копию вручную:

- весь список валиден → `ready`;
- проблемы остались → остаёмся в `blocked`;
- сохранение или повторная загрузка завершились ошибкой → показываем ошибку, сохраняя текущий список.

### `ready`

Справа отображается проверенный список файлов:

- для фильма — исходные видеофайлы без выдуманной классификации;
- для сериала/аниме — канонические эпизоды и группы в порядке ARM;
- для специальных выпусков — название группы, канонический номер/ordinal и тип группы;
- для объединённого файла — один элемент с несколькими каноническими целями.

Клик по элементу → `preparing`.

### `preparing`

Источник разрешает конкретный файл в `PlaybackInfo`. Выбранный элемент остаётся подсвеченным, поверх него показывается локальный индикатор загрузки. Повторный клик не создаёт второй запрос.

Результаты:

- получен корректный descriptor → `playing`;
- прогрев потока нужен → `playing`, а сам плеер показывает waiting/buffering overlay;
- descriptor пустой или запрос завершился ошибкой → возврат в `ready` с ошибкой у выбранного элемента.

### `playing`

Слева в том же контейнере preview заменяется inline-плеером. Справа остаётся тот же список, но его роль становится очередью. Активный элемент подсвечен.

Переходы:

- выбор другого элемента → `preparing`, затем обновление существующего плеера без пересоздания всего workspace;
- завершение элемента → следующий элемент очереди, если он существует и разрешён;
- «Назад к раздачам» → остановка плеера и `browsing`;
- закрытие/назад внутри workspace → `ready`, без открытия другого плеера;
- кнопка fullscreen → browser fullscreen, без замены shell и панели.

### `failed`

Ошибка принадлежит конкретной операции: поиск, загрузка файлов, сохранение соответствия или подготовка потока. Пользователь видит сохранённый контекст и может повторить только упавший шаг либо вернуться к раздачам.

## Единый workspace

### Постоянные элементы

- глобальная верхняя панель;
- ограниченный общей шириной страницы shell;
- левая media-stage;
- правая панель контекста;
- фон текущего произведения.

### До начала просмотра

Слева:

- backdrop/preview произведения;
- состояние «Загрузка файлов», «Выберите файл» или «Исправьте соответствия»;
- внизу по центру малозаметное полное название раздачи.

Справа:

- заголовок выбранной раздачи;
- список файлов/эпизодов;
- состояние сопоставления;
- вход в режим исправления;
- кнопка возврата к списку раздач.

### После начала просмотра

Слева:

- inline-плеер 16:9;
- название произведения не дублируется поверх видео;
- название раздачи остаётся доступно в служебной подписи/информации, но не перекрывает контент.

Справа:

- обычный просмотр: очередь;
- совместный просмотр: единственная `WatchTogetherRail` с вкладками `Чат / Очередь / Участники`;
- список и выбранный элемент не пересоздаются при переключении вкладок.

## Глубокий module подготовки просмотра

Сложность выбора источника, проверки файлов, исправления и получения `PlaybackInfo` должна находиться за одним интерфейсом. Рабочее название module: `ReleasePlaybackFlow`.

Его внешний интерфейс должен быть малым:

```ts
interface ReleasePlaybackFlow {
  state: ReleasePlaybackState;
  selectRelease(release: RawStreamPayload): void;
  selectItem(itemId: string): void;
  applyRepair(command: RepairCommand): void;
  retry(): void;
  back(): void;
}
```

Рендер страницы не должен знать:

- какую команду SDK вызвать для конкретного источника;
- как различаются torrent/HLS/MP4;
- как строится ARM binding;
- как работает generation/cancellation;
- как собирается playlist;
- когда допустимо писать прогресс.

Внутри module находятся адаптер источника, нормализация ответа, validation gate, построение очереди и подготовка descriptor. Интерфейс module одновременно является основной поверхностью тестирования.

## Нормализованная модель файла

Каждый элемент списка приводится к одной форме:

```ts
interface ReleaseItem {
  id: string;
  fileName: string;
  displayTitle: string;
  sizeLabel?: string;
  stillSrc?: string;
  status: "resolved" | "ambiguous" | "unresolved" | "ignored";
  targets: PlaybackTarget[];
  progressTarget: ProgressTarget | null;
}
```

`PlaybackTarget` может указывать на фильм, один эпизод или несколько эпизодов объединённого файла. Числа сезона и серии без канонических идентификаторов не считаются достаточным основанием для записи прогресса, если источник поддерживает ARM binding.

`ignored` нужен для sample, NCOP/NCED, трейлеров и технических файлов, которые пользователь сознательно исключил из очереди. Игнорирование является сохранённым исправлением раздачи, а не временным фильтром интерфейса.

## Validation gate

### Фильм

- торрент всегда требует показа списка;
- автоматического определения главного файла нет;
- любой явно выбранный воспроизводимый видеофайл может быть запущен;
- прогресс относится к фильму, а не к имени файла;
- невоспроизводимые файлы отображаются отключёнными либо исключаются адаптером источника.

### Сериал и аниме

Раздача готова к запуску, только когда каждый воспроизводимый файл имеет один из статусов:

- `resolved` с канонической целью;
- `ignored` по явному сохранённому решению.

`ambiguous` и `unresolved` блокируют всю раздачу, потому что иначе очередь может автоматически перейти на неверный эпизод.

### Объединённые серии

Один файл может покрывать несколько канонических эпизодов. Он остаётся одним элементом очереди и передаёт в descriptor все `episodeIds/targets`. Прогресс отдельных эпизодов отмечается только по правилам backend/domain progress; frontend не выдумывает границы внутри файла.

### Specials, OVA, ONA и фильмы внутри аниме-франшизы

Тип группы и порядок приходят из ARM. UI показывает локализованное название entry/group и `displayOrdinal`. Фронтенд не превращает специальные группы в «сезон 0», если существует каноническая структура ARM.

## Матрица сценариев

| Сценарий | После выбора источника | Условие запуска | После запуска |
|---|---|---|---|
| Фильм, прямой HLS/MP4 | Сразу `preparing` | Получен `PlaybackInfo` | Inline-плеер, без очереди файлов |
| Фильм, торрент, один файл | Встроенный список из одного файла | Явный клик пользователя | Inline-плеер, файл остаётся справа |
| Фильм, торрент, несколько файлов | Все видеофайлы списком | Явный выбор любого файла | Выбранный файл подсвечен |
| Сериал, корректный сезон | Канонические серии списком | Все файлы resolved/ignored | Очередь сезона, автопереход разрешён |
| Сериал, неверный offset | Заблокированный список | Сохранён anchor/pin и повторная проверка успешна | Очередь из исправленных серий |
| Аниме с несколькими арками | Группы ARM в каноническом порядке | Все группы разрешены | Очередь сохраняет структуру групп |
| Аниме со specials/OVA | Отдельные канонические группы | Файлы resolved либо явно ignored | Корректные progress targets |
| Файл соответствует нескольким сериям | Один item с несколькими targets | Binding однозначен | Один playback item, несколько целей |
| Sample/NCOP/бонус | Видимый unresolved item | Пользователь сопоставил или пометил ignored | В очередь не попадает, если ignored |
| Источник вернул пустой список | Ошибка внутри workspace | Повторная загрузка либо назад | Плеер не открывается |
| Подготовка потока упала | Ошибка выбранного item | Retry конкретного item | Список и исправления сохраняются |
| Гость совместного просмотра | Получает descriptor и очередь хоста | Host session active | Тот же workspace и `WatchTogetherRail` |

## Совместный просмотр

- Хост проходит тот же pipeline, что и одиночный пользователь.
- Комната создаётся вокруг уже выбранной раздачи и её проверенной очереди.
- Гость получает нормализованную очередь и descriptor активного item, а не заново угадывает файлы.
- Исправлять соответствия может только хост.
- Переключение вкладок панели не влияет на player portal и не пересоздаёт видео.
- Закрытие комнаты или выход возвращает в предыдущее состояние страницы и останавливает текущий playback; новый полноэкранный плеер не создаётся.

## Навигация

Кнопка Back имеет детерминированный смысл:

| Состояние | Действие |
|---|---|
| `browsing` | Возврат на страницу произведения |
| `inspecting` | Отмена запроса, возврат к раздачам |
| `blocked` / repair | Выход из repair → список файлов; следующий Back → раздачи |
| `ready` | Возврат к раздачам |
| `preparing` | Отмена подготовки, возврат к `ready` |
| `playing` | Остановка плеера, возврат к `ready` |

Browser history не используется для внутренних состояний workspace. Она меняется только при входе на страницу раздач и выходе с неё.

## Ошибки и конкурентные запросы

- Каждый выбор раздачи и файла получает generation id и `AbortSignal`.
- Ответ применяется только если generation совпадает с текущей.
- Выбор новой раздачи отменяет загрузку файлов, ARM layout, metadata и подготовку предыдущего потока.
- Ошибка deferred metadata не закрывает уже работающий плеер.
- Ошибка сохранения repair не уничтожает текущий список и выбранные значения.
- При восстановлении страницы из session storage данные повторно валидируются источником; сохранённый UI snapshot не считается источником истины.

## Прогресс и идентичность

Прогресс начинает записываться только в `playing`, когда descriptor содержит валидный `ProgressTarget`:

- фильм — идентичность произведения;
- серия — канонический episode/progress id;
- объединённый файл — список canonical targets согласно backend-контракту;
- unresolved/ambiguous — запись прогресса запрещена.

Название файла или вычисленные фронтендом `SxxEyy` не являются идентичностью прогресса.

## План проверки реализации

Тесты проходят через интерфейс `ReleasePlaybackFlow`, а не через внутренние флаги.

Обязательные группы:

1. Переходы всех состояний и Back для каждого состояния.
2. Матрица фильм/direct/torrent, сериал, аниме, specials, joined files.
3. Validation gate: ambiguous/unresolved блокируют episodic release; ignored разблокирует.
4. Отмена и игнорирование поздних ответов при быстрой смене раздачи/файла.
5. Плеер всегда получает page portal target; `document.body` не используется как автоматический fullscreen fallback.
6. В production-коде существует одна правая панель совместного просмотра — `WatchTogetherRail`.
7. Верхняя панель остаётся видимой до явного browser fullscreen.
8. Переключение эпизода обновляет существующий player instance без потери аудиодорожки и состояния комнаты.
9. Progress events не отправляются для неразрешённых целей.
10. Визуальные и interaction-проверки desktop/2K/mobile выполняются без отдельной логики данных для breakpoint.

## Вне текущего объёма

- автоматическое определение «главного фильма» по размеру или имени файла;
- автоматическое сопоставление неизвестного файла только на фронтенде;
- отдельные альтернативные панели для fullscreen, гостя или фильма;
- изменение backend-алгоритма ARM;
- вычисление временных границ нескольких эпизодов внутри объединённого видео.
